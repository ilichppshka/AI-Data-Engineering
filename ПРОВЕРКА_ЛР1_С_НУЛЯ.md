# Проверка ЛР 1 с нуля

## Суть ЛР 1

ЛР1 показывает полный путь от исходных файлов до простого ежедневного отчёта:

```text
CSV-файлы → сырой слой → соединение заказов с позициями → отчёт daily
```

Нужно построить таблицу `daily`, где одна строка означает один календарный
день покупки. В ней считаются количество заказов, количество товарных позиций,
выручка и доставка.

Главная инженерная проблема — у одного заказа может быть несколько позиций.
Если соединить таблицы и сразу считать строки, заказ размножится. Поэтому
позиции сначала приводят к нужному уровню, а затем соединяют с заказами. Для
сохранения заказов без позиций используется `LEFT JOIN`, а их показатели
заполняются нулями.

В работе также закрепляются три правила:

- сырой слой сохраняется без изменений, чтобы расчёт можно было повторить;
- обработка является пакетной: берём накопленный набор данных и строим отчёт;
- результат сверяется с источником по количествам и суммам.

Итог ЛР1 — витрина `daily`, сохранённая в Parquet. Её зерно — один календарный
день, а не одна позиция и не один заказ.

Эта инструкция рассчитана на новый компьютер, где репозиторий ещё не
клонировали. Команды ниже выполняются из терминала.

## 5. Что именно проверяет ЛР 1

Проверка убеждается, что результат `daily`:

- содержит одну строку на календарную дату;
- содержит все даты из исходных заказов;
- не изменяет число заказов после соединения таблиц;
- сохраняет все 8000 заказов и 9653 товарные позиции в текущем учебном наборе;
- правильно суммирует выручку и доставку;
- не содержит пропусков в итоговых показателях;
- хранит количества как целые числа.

## Краткий глоссарий ЛР 1

| Термин | Определение |
|---|---|
| **Ingestion (приём данных)** | Получение данных из внешнего источника и перенос их в нашу систему. |
| **Raw layer (сырой слой)** | Данные в исходном виде, без исправлений и преобразований. В проекте это `data/raw/olist/`. |
| **Grain (зерно таблицы)** | Что означает одна строка таблицы. В `daily` одна строка означает один календарный день. |
| **JOIN (соединение)** | Сопоставление строк разных таблиц по общему ключу, например `order_id`. |
| **Fan-out (размножение строк)** | Ошибка, при которой одна строка заказа после соединения превращается в несколько строк из-за нескольких товарных позиций. |
| **LEFT JOIN** | Соединение, которое сохраняет все строки левой таблицы, даже если пары в правой таблице нет. Поэтому заказ без позиций не пропадает. |
| **Витрина (daily_orders)** | Подготовленная итоговая таблица для отчёта или следующего потребителя данных. |
| **Batch processing (пакетная обработка)** | Обработка накопленного набора данных целиком; ЛР 1 строит ежедневный отчёт именно так. |
| **Streaming (потоковая обработка)** | Обработка событий по мере их поступления, почти без ожидания полного набора. |
| **Idempotency (идемпотентность)** | Свойство повторного запуска давать тот же результат, а не дублировать данные. |
| **Сверка с источником** | Проверка, что итоговые количества и суммы совпадают с исходными таблицами. |

## Колонки итоговой таблицы `daily`

| Колонка | Смысл |
|---|---|
| `order_date` | Дата покупки из `order_purchase_timestamp`. |
| `n_orders` | Число заказов за день. |
| `n_items` | Число товарных позиций за день. |
| `revenue` | Сумма `price` по товарным позициям. |
| `freight` | Сумма `freight_value` по товарным позициям. |
